# เขียน "วิธียิง" จากรูปไลน์อัพ — คู่มือสำหรับผู้ดูรูป

คุณดูรูปไลน์อัพ VALORANT ทีละใบด้วยตาจริง แล้วเขียน **วิธียิงสั้นๆ ภาษาไทย** ที่โปรแกรมจะ*อ่านออกเสียง*ให้ผู้เล่นฟังระหว่างเกม
ผู้เล่นเห็นรูปอยู่แล้ว เสียงมีไว้ย้ำขั้นสำคัญโดยไม่ต้องละสายตา — **ถูก สำคัญกว่าครบ · ไม่แน่ใจ = ใส่ ? ห้ามเดา**

> หลักทั้งหมดข้างล่างมาจากเจ้าของคลังเขียนตัวอย่างให้ดูเองพร้อมเหตุผล (29/09/2026)
> ร่างรอบแรกผิดเกือบหมดเพราะอ่านรูปแบบคนดูฉาก ไม่ใช่แบบคนทำไลน์อัพ — อ่านให้ครบก่อนเริ่ม

## ไฟล์ (อยู่โฟลเดอร์เดียวกับไฟล์นี้)
- `input-<ชุด>.json` → `items`: แต่ละใบมี `rel` (คีย์ตอนตอบ), `image` (เปิดด้วย Read — **ต้องเปิดทุกใบ**),
  `agent`, `ability_th` (สกิล — เชื่อได้), `map`, `side`, `site`, `title` (ชื่อใบ = ยืนไหนไปไหน)

## ขั้นแรก: แยกให้ออกว่าแต่ละช่อง/กรอบในรูปบอกอะไร
รูปหนึ่งใบมีหลายช่อง (เลข 1 2 3 …) หรือเป็นภาพเดียวที่มีกรอบเล็กแปะมุม — **แต่ละช่องมีหน้าที่ต่างกัน อย่าเอาช่องผิดมาเป็นจุดเล็ง**
- **ช่อง/กรอบจุดยืน**: มองลงพื้นหรือมองไปที่ขอบ/มุมที่ต้องยืนชิด มักมีวงซูม/เครื่องหมายบอกตำแหน่งเท้า
  - รูปที่เจ้าของทำเอง: **กรอบซ้ายล่าง = จุดยืน** (มองไปที่ขอบหน้าต่าง/มุมที่ต้องชิด)
- **ช่อง/กรอบจุดเล็ง**: มี **วงซูม, กล้องเล็ง (scope), ลูกศรแดง** จ่ออยู่ — นี่คือที่ที่ต้องอธิบายละเอียดที่สุด
  - รูปที่เจ้าของทำเอง: **กรอบซ้ายบน = จุดเล็ง** (ของบนหน้าจอทับกับของในฉาก)
- **ช่องผลลัพธ์/ช่องที่เห็นสกิลลอยหรือวางแล้ว** (เช่นมีเพชรฟ้า/กรง/ลูกศรปักอยู่) = **ไม่ใช่จุดเล็ง** ไม่ต้องอธิบาย
- ช่องที่ตัวเลขสีแดงเขียนไว้ (เช่น **1.5**) = ค่าชาร์จที่คนทำบอกไว้ เชื่อตัวเลขนั้น

## เขียนแบบนี้ (สำนวนของเจ้าของคลัง)
ลำดับ: **ยืน → เล็ง → (โซวา) เด้ง → ชาร์จ** · สั้น กระชับ ตัวเลขเขียนเป็นตัวเลขได้ · สะกด "ชาจ" ตามเจ้าของ

### ยืน
- บอก**ตำแหน่งเทียบกับของรอบตัว** ไม่ใช่ชื่อโซน: `ยืนชิดซ้ายบนขอบหน้าต่าง`, `ยืนชิดขอบรั้วทางเข้า B`, `ยืนหน้ากล่องเขียว`
- **ห้าม** `ยืนที่ A Tower` / `ยืนใน B Main` — ชื่อใบบอกอยู่แล้ว ไม่ช่วยอะไร
- เรียกของด้วย*หน้าตาที่เห็น*: กล่องเขียว, ขอบรั้ว, ขอบหน้าต่าง, ป้าย

### เล็ง — ส่วนสำคัญที่สุด
- บอก **"เอาส่วนไหนไปแนบกับส่วนไหน"** ให้ชัดทั้งสองฝั่ง
- **จุดอ้างอิงในฉาก**: ของที่เห็นชัดและไม่ขยับ — หลอดไฟ, ขอบบนของป้าย, ขอบ/ปลายของฟ้าแตก (รอยแตกสีม่วงบนฟ้าของ Ascent), มุมหลังคา
  ระบุส่วนย่อยเสมอ: ขอบบน / ปลาย / ส่วนเกือบปลาย / มุมซ้าย
- **ของบนหน้าจอที่ใช้แนบ (โซวาใช้บ่อยมาก แทนเป้ากลางจอ)**:
  - ไอคอนสกิลบนแถบล่างของจอ เช่น `ให้ส่วนบนของไอคอนสกิลอันติทับกับหลอดไฟ`
  - ลูกเด้ง (สี่เหลี่ยมข้าวหลามตัดใต้แถบชาร์จ) เช่น `ใช้ลูกเด้งลูกที่ 2 แนบส่วนเกือบปลายของฟ้าแตก`
  - เส้นแบ่งช่องของแถบชาร์จ เช่น `ใช้เส้นแบ่งช่องแรกของแถบชาจแนบกับขอบฟ้าแตก`
- บอกทิศถ้ารูปชี้ (`เล็งขวา`, `เงยขึ้น`)
- ตัวอย่างที่ผิด: `เล็งรูปลูกศรประดับบนหลังคา` (อ่านลูกศรแดงที่คนทำวาดชี้เป็นของในฉาก), `เล็งเสาอากาศไกลๆ` (เดาเอง)

### โซวาเท่านั้น: เด้ง + ชาจ (ต้องเป๊ะ)
- **เด้ง** = นับลูกข้าวหลามตัดใต้แถบชาร์จที่**ถูกทำสี/ติดไฟ** (ลูกว่างไม่นับ): 0, 1 หรือ 2 เด้ง
- **ชาจ** = แถบชาร์จแบ่ง 3 ช่อง ดูว่าแถบสีฟ้า/สีแดงยาวถึงไหน
  - เต็มช่องพอดี = 1, 2, 3 · **เลยเส้นแบ่งไปนิดหน่อย / ครึ่งช่อง = .5** เช่น เลยเส้นที่ 1 มานิดหน่อย = `1.5`
  - มีตัวเลขสีแดงเขียนในรูป = ใช้ตัวเลขนั้น
- **ยิงหลายลูกในใบเดียว** (Double shock ฯลฯ): แยกเป็น `ลูกแรก … ลูกที่2 …` แต่ละลูกมีเล็ง/ชาจ/เด้งของตัวเอง

### ตัวละครอื่น (ไม่ใช่โซวา) — ไม่ต้องเป๊ะเท่า
สกิลขว้าง/โยนของตัวอื่นตกเป็นวงกว้าง เขียนแค่ **ยืนไหน + เล็งอะไร (+ ท่าพิเศษถ้ารูปบอก เช่น กระโดดโยน, คลิกขวา)** ก็พอ

### ห้ามใส่
- **ผลลัพธ์/จุดตก**: `ให้ตกปิดทาง B Main`, `ขว้างข้ามตึกไปตกที่ Generator` — ชื่อใบบอกแล้ว
- ชื่อสกิล/ชื่อใบซ้ำ, ชื่อโซนของจุดยืน

## ห้ามเดา
- ส่วนไหนมองไม่ชัด **ใส่ `?` แทนค่า** เช่น `ชาจ ?` `? เด้ง` แล้วตั้ง `"unsure": true` — ผู้ใช้เติมเอง
- รูปไม่มีข้อมูลพอบอกวิธียิงเลย → `"howto": ""`

## ตอบ: เขียน `out-<ชุด>.json` (ชื่อเดียวกับ input แค่เปลี่ยน input → out)
```json
{"<rel>": {"howto": "ยืน... เล็ง... 2 เด้ง 1.5 ชาจ", "unsure": false}}
```
- ต้องมีครบทุก `rel` ใน input · ห้ามแก้/ย้าย/ลบไฟล์อื่น
