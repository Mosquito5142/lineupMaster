# รวมคลังจากโฟลเดอร์อื่น — Design

## ปัญหา

ผู้ใช้มีสองเครื่อง (PC กับ mos) ย้ายข้อมูลกันผ่าน Google Drive โดยโหลดทั้งโฟลเดอร์ `dist/LineupMaster/`
ไปแตกทับของเดิม ผลคือ **ของที่อีกเครื่องเพิ่มไว้เองหายหมด** (รูป หมุด แท็ก ชื่อโซน) ทั้งสองเครื่อง
เพิ่มไลน์อัพของตัวเองได้ จึงต้องรวมกันสองทาง

## ขั้นตอนที่ผู้ใช้จะทำ (ตกลงกันแล้ว)

1. โหลดเวอร์ชันใหม่จาก Drive ไปวางที่**ใหม่** เช่น `Desktop\LineupMaster-ใหม่` (ไม่แตกทับของเก่า)
2. เปิดหน้าจัดการคลังจากโฟลเดอร์ใหม่ → ปุ่ม **"รวมคลังจากโฟลเดอร์อื่น"** → เลือกโฟลเดอร์เก่า
3. ดูหน้าสรุป ติ๊กเฉพาะรายการที่ไม่แน่ใจ แล้วกดรวม
4. ใช้โฟลเดอร์ใหม่ต่อ โฟลเดอร์เก่าไม่ถูกแตะเลย ใช้เป็นสำรองได้
5. อัปโหลดโฟลเดอร์ใหม่ขึ้น Drive ให้อีกเครื่องรวมกลับแบบเดียวกัน

ตัวรวมรวม **โฟลเดอร์อื่น (THERE) เข้าโฟลเดอร์ที่เปิดอยู่ (HERE)** เสมอ **อ่านอย่างเดียวจาก THERE**
ใช้ได้ทั้งสองทิศ (เครื่อง B รวมของเก่าตัวเองเข้าเวอร์ชันใหม่ หรือเครื่อง A รวมของจาก Drive เข้าตัวที่ใช้อยู่)

## ข้อมูลที่รวม

ทุกไฟล์คีย์ด้วย rel ของรูป (`ascent/attack/sova/A/xxx.png`) จึงรวมรายคีย์ได้

| ของ | วิธีรวม |
|---|---|
| `lineups/` รูป + ของพ่วง (`.txt .md .gif`) | รูปที่ THERE มีแต่ HERE ไม่มี → ก๊อปพร้อมของพ่วง (ดูกติกาลบ/เปลี่ยนชื่อข้างล่าง) · rel เดียวกันแต่ไฟล์ต่างกัน → ขัดกัน |
| `positions.json` (หมุด + ป้ายจุด `map/@site-x`) | รายคีย์ · คีย์ที่มีฝั่งเดียว → เพิ่ม · มีทั้งคู่ต่างกัน → ขัดกัน |
| `meta.json` | รายช่อง: `tags` = รวมกัน · `drilled` = ค่ามากกว่า · `fav` = true ถ้าฝั่งไหนเป็น true · `ability` ต่างกัน → ขัดกัน |
| `callouts.json` | ราย map/คีย์ · มีฝั่งเดียว → เพิ่ม · `label`/`xy` ต่างกัน → ขัดกัน |
| `browse.json` | `taken` รวมกัน (rel แปลงผ่านบันทึกการเปลี่ยนชื่อ) · `skipped` รวมกัน |
| `last-view.json` `uses` | ค่ามากกว่า (**ไม่บวก** เพราะสองโฟลเดอร์มักแตกมาจากชุดเดียวกัน บวกแล้วนับซ้ำ) |
| `changes.json` (ใหม่) | รวมบันทึกทั้งสองฝั่ง ไว้ใช้รอบถัดไป |

**ขัดกัน** = ขึ้นในหน้าสรุปทีละรายการ ค่าเริ่มต้น **เก็บของ HERE** เลือกเอาของ THERE ได้
ยกเว้น **รูปชื่อซ้ำแต่เนื้อต่าง** (ผู้ใช้เลือกเพิ่มทีหลัง): ค่าเริ่มต้น **เอาไฟล์ที่แก้ล่าสุด** (เวลาแก้ไฟล์ต่างกันเกิน 2 วินาที)
และมีตัวเลือก "เก็บทั้งคู่" (ของ THERE ได้ชื่อใหม่ในโฟลเดอร์เดียวกัน) · รูปจำจากเนื้อไฟล์ (sha1) ไม่ใช่ชื่อ
ของที่ถูกแทน (รูป) ย้ายเข้า `.trash/` ก่อนเสมอ

### ค่าเฉพาะเครื่อง

`capture.json`, `compose.json`, และ `map`/`side`/`f_agent` ใน `last-view.json` เป็นของเครื่องใดเครื่องหนึ่ง
ต้องเอามาจากโฟลเดอร์ที่ **เคยเปิดบนเครื่องนี้**

- โปรแกรมหลักเขียน `"machine": <COMPUTERNAME>` ลง `last-view.json` ทุกครั้งที่บันทึก (เพิ่มคีย์เดียว ของเดิมไม่เปลี่ยน)
- ค่าเริ่มต้น: เอาจากฝั่งที่ `machine` ตรงกับเครื่องนี้ · ตรงทั้งสองหรือไม่ตรงเลย → THERE
- หน้าสรุปมีตัวเลือก "ค่าเฉพาะเครื่อง: ใช้ของ [โฟลเดอร์นั้น / โฟลเดอร์นี้]" ให้เปลี่ยนเองได้

`config.yaml` และ `aliases.yaml`: ใช้ของ HERE (มากับโปรแกรม) ถ้าของ THERE ต่างกัน หน้าสรุปขึ้น
ตัวเลือก "ใช้ของโฟลเดอร์นั้นแทน" (ค่าเริ่มต้น: ไม่ใช้) · คีย์ที่ของเก่าไม่มีจะได้ค่าเริ่มต้นจาก `config.py` เองอยู่แล้ว

## ลบ / เปลี่ยนชื่อ (ผู้ใช้เลือก: ถามทุกครั้ง)

**บันทึก** `changes.json` ที่ ROOT: รายการ `{"old": rel, "new": rel|null, "at": ISO เวลา}`
เขียนใน `library.migrate()` ซึ่งเป็นจุดเดียวที่ลบ/เปลี่ยนชื่อ/ย้ายทุกทางวิ่งผ่าน (หน้าเว็บ, หน้าต่าง Qt เดิม, ตัวต่อรูป)
รายการซ้ำระหว่างสองฝั่ง (old/new/at ตรงกัน) = ประวัติร่วม ทำไปแล้วทั้งคู่ ข้าม

กติกา (ทำอัตโนมัติ เพราะมีบันทึกยืนยัน):
- บันทึกของ HERE บอก X→Y (เปลี่ยนชื่อที่นี่): X ของ THERE คือใบเดียวกับ Y ไม่ก๊อป แต่รวมหมุด/แท็กของ X เข้า Y
- บันทึกของ HERE บอก X ถูกลบ: X ของ THERE ไม่ก๊อป (ขึ้นในสรุปว่า "ลบไปแล้วที่นี่")
- บันทึกของ THERE บอก X→Y และ HERE ยังมี X: เปลี่ยนชื่อ X ของ HERE เป็น Y (ผ่าน `library.move/rename` ของพ่วงและคีย์ตามไป)
- บันทึกของ THERE บอก X ถูกลบ และ HERE ยังมี X: ลบ X ของ HERE (เข้า `.trash/`)

**ไม่แน่ใจ** (ขึ้นให้ติ๊กเอง ค่าเริ่มต้นคือทางที่ไม่ทำให้ของหาย/ไม่ซ้ำ):
- รูปใหม่จาก THERE ที่**เนื้อไฟล์ตรงกับรูปอื่นใน HERE** (น่าจะถูกเปลี่ยนชื่อด้วยมือ) → ค่าเริ่มต้น: ไม่ก๊อป
- รูปใหม่จาก THERE ที่อยู่ใน `.trash/` ของ HERE ด้วย path เดียวกัน (ลบก่อนมีบันทึก) → ค่าเริ่มต้น: ไม่ก๊อป
- รูปของ HERE ที่ THERE ไม่มี แต่อยู่ใน `.trash/` ของ THERE (อีกเครื่องลบก่อนมีบันทึก) → ค่าเริ่มต้น: เก็บไว้

## ส่วนประกอบ

| หน่วย | หน้าที่ | พึ่ง |
|---|---|---|
| `src/lineupmaster/journal.py` | อ่าน/เพิ่มบันทึก `changes.json` | — |
| `library.migrate()` | เรียก `journal.record(root, old, new)` | journal |
| `browser.save()` | เพิ่ม `"machine"` | — |
| `src/lineupmaster/merge.py` | `plan(here, there) -> Plan` (อ่านอย่างเดียวทั้งสองฝั่ง) · `apply(here, there, plan, choices) -> Report` | journal, library, positions, meta |
| `tools/web_manage.py` | `GET /api/merge/candidates` (หาโฟลเดอร์ที่มี `lineups/` แถว Desktop/Downloads/โฟลเดอร์แม่) · `POST /api/merge/preview {path}` · `POST /api/merge/apply {path, choices}` แล้ว `store.reload()` | merge |
| `assets/web/` | ปุ่ม "รวมคลัง…" + dialog: เลือกโฟลเดอร์ (รายการที่เจอ หรือวาง path) → หน้าสรุป (ตัวเลข, รายการไม่แน่ใจ/ขัดกันให้ติ๊ก, ค่าเฉพาะเครื่อง, config) → รวม → ผลสรุป | API |

`Plan` เป็นข้อมูลล้วน (serialize เป็น JSON ได้) แต่ละรายการมี `id` ให้ `choices` อ้างถึง
`apply` ตรวจซ้ำว่า THERE/HERE ไม่เปลี่ยนไปจากตอน plan (เทียบจำนวนรูป + เวลาแก้ไฟล์ json) ถ้าเปลี่ยนให้ plan ใหม่

## ความปลอดภัย

- ไม่เขียนอะไรลง THERE เลย
- ไม่ลบไฟล์ถาวร: ทุกอย่างที่ถูกแทน/ลบเข้า `.trash/<เวลา>-merge/`
- ก่อนเขียน json ใดๆ ก๊อปไฟล์เดิมเก็บไว้ที่ `.trash/<เวลา>-merge/` ด้วย (ย้อนกลับได้ด้วยมือ)
- THERE ต้องเป็นโฟลเดอร์ที่มี `lineups/` และไม่ใช่ HERE เอง (ตรวจด้วย path ที่ resolve แล้ว)
- ทางเข้า API ใช้โทเคนเดิมของ web_manage
- หลังรวมบอกให้ปิดแล้วเปิดโปรแกรมหลักใหม่ (โปรแกรมหลักโหลดหมุดตอนเปิดเท่านั้น)

## ทดสอบ

- `tests/test_merge.py` (unittest ใน stdlib ไม่มี pytest ในเครื่อง) สร้างสองโฟลเดอร์จำลองใน temp dir:
  รูปใหม่ฝั่งเดียว, rel ชนกันไฟล์ต่าง, หมุด/แท็กขัดกัน, เปลี่ยนชื่อ/ลบมีบันทึกทั้งสองทิศ, ไม่แน่ใจสามแบบ,
  ประวัติร่วม, ค่าเฉพาะเครื่อง, THERE ไม่ถูกแตะ (เทียบ hash ทั้งโฟลเดอร์ก่อน/หลัง)
- `tests/test_journal.py`: remove/rename/move ผ่าน library แล้วมีบันทึกถูกต้อง
- ลองจริงในเบราว์เซอร์: ก๊อป `dist/LineupMaster` เป็นสองชุดใน temp แก้ต่างกันแล้วรวม

## ไม่ทำ (YAGNI)

- รวมสามทางแบบ git หรือเก็บประวัติการแก้หมุด/แท็กรายช่อง (ขัดกันให้ผู้ใช้เลือกแทน)
- อัปเดตตัวโปรแกรมผ่านตัวรวม (ผู้ใช้เอาโปรแกรมใหม่มาทั้งโฟลเดอร์อยู่แล้ว)
